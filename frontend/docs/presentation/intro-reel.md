# 서비스 소개 영상 릴 (`/intro`)

> 1분짜리 서비스 소개 영상을 **화면 녹화 한 번으로** 뽑기 위한 자동 재생 페이지다.
> 구현: [`src/app/intro/`](../../src/app/intro/). 제품 화면이 아니라 녹화용이라 랜딩에 진입점이 없다.

## 찍는 법 (Windows)

준비:

1. `npm run dev`로 띄운다.
2. `http://localhost:5173/intro`를 열고 **한 번 끝까지 재생시킨다.** 이 한 번이 웹폰트와
   게임 청크(three.js·rapier)를 캐시에 채운다 — 안 하면 첫 씬과 게임 화면이 늦게 뜬다.
3. `F11`로 전체화면. **모니터가 16:9면 무대가 화면을 꽉 채워** 검은 여백 없이 떨어진다.
4. 화면을 한 번 클릭한다 — 자동재생 정책 때문에 BGM은 첫 클릭 뒤에 켜진다. 소리를 편집에서
   따로 얹을 거면 건너뛴다.
5. Windows 설정 → 접근성 → 시각 효과에서 **애니메이션 효과가 켜져 있는지** 확인한다
   (꺼져 있으면 `prefers-reduced-motion`이라 등장 연출이 전부 사라진다).

녹화 — **게임 바**(설치 없음, 소리까지 같이 녹음):

6. `Win`+`Alt`+`R` → 녹화 시작(포커스된 창을 녹화한다. 전체화면 브라우저면 화면 전체다).
7. `F5`로 새로고침 → 그 순간부터 릴이 처음부터 굴러간다.
8. 62.5초 뒤 마지막 씬에서 멈춘다. `Win`+`Alt`+`R`로 정지.
9. 결과물: `내 PC\영상\캡처\*.mp4`. 앞뒤 몇 초를 잘라내면 끝이다.

게임 바가 안 열리면 설정 → 게임 → Xbox Game Bar를 켠다. 대안 둘:

- **스니핑 도구**: `Win`+`Shift`+`S` → 상단에서 캠코더 아이콘 → 영역 지정 → 녹화.
  화면 일부만 딸 때 편하다.
- **OBS Studio**(설치 필요): 캔버스를 1920×1080으로 두고 「창 캡처」로 브라우저를 잡는다.
  비트레이트·프레임을 지정할 수 있어 제출용 화질이 필요하면 이쪽이다.

무대는 항상 16:9로 고정되고 남는 자리는 검게 둔다 — 창 크기가 어중간해도 구도는 같다.
글자 크기는 무대 폭에 비례하므로(`cqw`) 1920×1080으로 찍든 1280×720으로 찍든 같은 그림이다.
16:9가 아닌 모니터에서 찍으면 검은 띠가 영상에 그대로 구워지니 편집에서 잘라낸다.

### 재촬영·손보기

| 쿼리 | 하는 일 |
|---|---|
| `?scene=N` | N번 씬부터 시작한다(0부터). 뒤 씬을 다시 찍으려고 앞을 기다리지 않는다 |
| `?scene=N&hold=1` | 그 씬을 **넘기지 않고 세워 둔다.** 배치·문구를 고칠 때 쓴다 |

```
http://localhost:5173/intro?scene=4&hold=1
```

## 대본

길이와 순서의 SSOT는 [`scenes.tsx`](../../src/app/intro/scenes.tsx)의 `REEL_SCENES`다.
영상을 늘리거나 줄이려면 그 표의 `ms`만 고친다.

| # | 씬 | 길이 | 내용 |
|---|---|---|---|
| 0 | `open` | 6.5s | **주사위 로고 스팅** → 워드마크 · "링크 하나로 모이면 바로 시작하는 파티 게임" |
| 1 | `problem` | 8.0s | 설치·가입·규칙에 취소선 → "YORR는 링크 하나." → **폰이 컨트롤러** |
| 2 | `join` | 8.5s | 3단계 입장 흐름 · **실제 QR**(배포 주소) · 대기실 폰 |
| 3 | `yacht` | 13.0s | **실제 요트 플레이 화면** — 굴리기 2회 → 초이스 기록 |
| 4 | `pingpong` | 11.0s | **실제 탁구 플레이 화면** — AI와 자동 랠리 |
| 5 | `duel` | 11.0s | **실제 결투 플레이 화면** — 신호 → 뽑기 → 착탄, 2라운드 K.O. |
| 6 | `close` | 4.5s | 워드마크 · `yorr.site` |

## 로고 스팅

첫 씬은 **닌텐도 스위치 인트로의 문법을 주사위로 옮긴 것**이다 — 조이콘 두 짝이 양쪽에서
들어와 본체에 맞물리고 그 충격에서 로고가 서는 구조. 주사위 두 개(각각 6)가 무대 밖에서
굴러 들어와 가운데서 **딱 멈추고**, 그 순간 섬광과 함께 워드마크가 선다.

- 맞물리는 시각은 `scenes.tsx`의 `SNAP_AT`(900ms) 하나가 정한다 — 충격·섬광·워드마크가
  전부 이 값을 기준으로 서므로 한 줄만 고치면 스팅 전체 박자가 같이 움직인다.
- 도착에서 감속하지 않는다. 스위치 인트로의 맛은 부드럽게 만나는 게 아니라 딱 멈추는 데 있다.
- 주사위 몸통·눈 색은 게임의 물리 주사위와 **같은 토큰**(`physics-die`·`physics-pip`)을 쓴다.
- 이동 거리는 `%`(주사위 자기 폭의 배수)다 — `cqw`로 적으면 무대 폭에만 비례해 주사위
  크기와 어긋난다.
- **소리는 없다.** 스위치 인트로의 "딸깍"에 해당하는 효과음은 넣지 않았다 — 필요하면 편집에서
  맞물리는 프레임(0.9초 지점)에 얹는 게 정확하다.

## 게임 세 판 — 실제 플레이 화면

**지금 플레이할 수 있는 3종만** 싣는다(`games.ts`의 `live: true`). 준비 중인 라이어스
다이스·낚시는 영상에 넣지 않는다 — 보고 들어온 사람이 없는 걸 찾는다.

세 판 모두 **제품 화면을 그대로 태운다.** 영상용 목업도 캡처 이미지도 없으므로 게임을
고치면 릴도 같이 바뀐다. 화면이 무대를 **가득** 채우고, 릴 카피는 그 위에 얹는 하단 한 층이다.

| 게임 | 태우는 화면 | 서버 자리 | 조작 자리 |
|---|---|---|---|
| 요트 다이스 | `GamePlay` — 점수시트·라운드·타이머·물리 주사위 트레이 | 연습 모드의 1인 로컬 서버(`createTutorialClient`) | `YACHT_STEPS`가 **실제 버튼**을 누른다 |
| 탁구 | `LocalPingPongGame` — YOU:CPU 점수판·피드백·3D 코트 | 없음(로컬 게임). 상대는 진짜 AI | 컴포넌트의 `auto` 모드가 스스로 받아넘긴다 |
| 석양이 진다 | `DuelGame`의 껍데기 + `Arena` — 신호등·총알·이름표 | 없음 | `DUEL_BEATS` 대본이 무대를 넘긴다 |

세부 사항 세 가지:

- **요트는 상태를 밀어넣지 않고 버튼을 누른다.** 굴림 횟수·킵·기록은 화면과 로컬 서버가
  나눠 들고 있어서, 밖에서 상태만 갈아끼우면 실제로는 나올 수 없는 화면이 그려진다.
  누르는 표지는 `[data-tutorial="roll"]`·`[data-tutorial-category="choice"]` — 연습 모드
  안내가 가리킬 때 쓰는 것과 같은 표지라 클래스명이 바뀌어도 안 깨진다. `choice`(총합)를
  기록하는 이유는 굴림을 강제하지 않기 때문이다(다른 족보는 안 맞으면 0점이 찍힌다).
- **탁구의 `auto`는 제품 코드에 있다**(`LocalPingPongGame`). 릴에는 라켓을 휘두를 사람이
  없어서다. 이 판은 랭킹에 올리지 않는다(`saveResult`가 `auto`에서 빠진다). 스윙 타이밍은
  타격 창(0.72~1.06, 이상점 0.9)에서 0.06·0.1 이르게 번갈아 친다 — 스매시와 퍼펙트가 섞인다.
  한 값으로 고정하면 같은 피드백 문구만 반복되고, 0.16까지 벌리면 전부 아웃·네트가 되어
  랠리가 아예 서지 않는다(실측).
- **요트 화면의 온보딩 안내 둘은 릴에서 꺼둔다.** 소개 영상에 "이걸 눌러 보세요"가 뜨면
  시연이 아니라 사용설명서로 읽히고, 센서 패널은 정작 보여줘야 할 주사위 트레이를 덮는다.
  - 첫 진입 코치마크("빛나는 동그라미 두 개를…") → **프롭으로** 끈다. 아무것도 그리지 않는
    `guide={() => null}`을 넘기면 `coachOpen`이 서지 않는다. 쿠키(`hideTutorial()`)를 쓰지
    않는 이유는 그게 녹화용 브라우저에 1년짜리 흔적을 남기기 때문이다.
  - 센서 권한 패널(`MotionPermissionPanel`) → **CSS로** 가린다. 이건 화면이 센서 지원 여부를
    보고 스스로 띄우는 것이라 프롭 스위치가 없다. 잡는 것은 클래스가 아니라 접근 가능한
    이름(`[aria-labelledby="motion-permission-title"]`·`[aria-label="센서 권한 안내"]`)이다.
  - 헤더의 `?` 도움말 **버튼은 남긴다** — 알럿이 아니라 실제 UI고, 누르지 않으니 안 열린다.
- **`h-svh`는 CSS 한 줄로 되돌린다.** 제품 화면은 뷰포트 높이로 고정돼 있고 릴 무대는
  16:9로 잘라 낸 상자라 그냥 넣으면 아래가 잘린다. `reel.css`의 `.reel-screen :is([class*="h-svh"])`가
  무대 안에서만 100%로 바꾼다 — 레이어 밖 규칙이라 Tailwind utility보다 이기고, 그래서
  **제품 코드에는 릴을 위한 흔적이 남지 않는다.**

인원·소요 시간·조작 배지는 `games.ts`에서 그대로 읽는다. **룰 세 줄만 릴이 소유한다**
(영상 길이에 맞춘 요약이라 제품 화면의 규칙 설명과 문장이 다르다).

## 알아둘 것

- **씬 전환은 자르기(cut)다.** 크로스페이드가 없다. 리듬 때문이기도 하고(챕터가 흐려지며
  바뀌면 그 구간이 멈춘 것처럼 읽힌다), 성능 때문이기도 하다 — 두 씬이 겹치는 순간 요트의
  rapier 월드와 탁구 코트의 WebGL 컨텍스트가 같이 살아난다. 자르면 겹치는 프레임이 없다.
- **씬 안의 등장은 느리다.** 애니메이션 900ms + 항목 간격 800~1050ms
  ([`reel.css`](../../src/app/intro/reel.css)와 각 씬의 `animationDelay`). 전환과 반대
  방향으로 튜닝한 값이다 — 등장이 빠르면 읽기 전에 다 서 있어서 순서가 안 읽힌다.
- 등장 연출은 CSS keyframes다. 타임라인이라 `animation-delay`로 순서를 잡는 게 가장 싸고,
  이 요소들은 퇴장하지 않으므로 `motion`이 필요한 자리가 아니다.
- 릴 서체는 **펴진고딕**(jsdelivr CDN, `reel.css`의 `@font-face` + `.reel-stage`)이다.
  제품 화면에는 적용하지 않는다 — 앱 서체 SSOT는 `tokens.css`의 `--ds-font-sans`다.
  워드마크·숫자·대문자 라벨은 `font-mono`(Space Grotesk)로 남는다: 워드마크는 브랜드
  마크고 숫자는 디자인 시스템의 NUMERALS 규칙(tabular)을 따른다.
- **`font-mono` 안의 한글도 펴진고딕이다.** Space Grotesk에는 한글 글리프가 없어서, 스택을
  그대로 두면 한글만 뒤의 `ui-monospace`로 떨어져 시스템 고딕으로 그려진다(오프닝 부제와
  메타 배지가 실제로 그랬다). `reel.css`가 mono 스택 <b>중간에</b> 펴진고딕을 끼워
  글자 단위로 갈라 받는다 — 숫자·라틴은 그대로 Space Grotesk다.
- **첫 프레임에 폰트가 깨지지 않는다.** `font-display: block`이라 대체 서체로 잠깐 그려지는
  일이 없고, `IntroReel`이 `document.fonts.ready`까지 첫 씬을 붙잡는다. 캐시가 차 있으면
  이 대기는 사실상 0이다 — 그래도 「찍는 법」 2번(한 번 재생)을 건너뛰지 말 것.
- 모션 감소(`prefers-reduced-motion`) 설정이 켜진 기기에서는 등장 연출이 사라진다.
  **녹화용 기기에서는 꺼둔다.**
- BGM은 랜딩 사운드트랙(요트 트랙)을 그대로 쓴다. 나레이션을 얹을 거면 편집에서 낮춘다.
